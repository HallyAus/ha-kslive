# KSLive for Home Assistant

An unofficial HACS integration for active [KSLive](https://kslive.com.au) subscribers. It finds the KSLive audio broadcast and recent audiocasts, resolves a fresh subscriber stream, and sends it to one or more Home Assistant media players.

## Features

- Home Assistant UI login using your KSLive subscriber email and password.
- The password is exchanged for short-lived access/refresh tokens and is never stored.
- Automatic token refresh and Home Assistant reauthentication when required.
- Idle sleep enabled by default: no background subscriber requests or token refreshes while idle,
  including after a Home Assistant restart. Play, Refresh and Browse wake it on demand.
- Audio status sensor with current, upcoming, and latest-recording metadata.
- Spotify-style KSLive media player with browse, play, pause, stop, previous, and next controls.
- Output picker for individual configured speakers or all configured speakers at once.
- Automatic audio-only relay for Sonos speakers when KSLive supplies video-bearing HLS.
- KSLive-only Sonos EQ preset with saved bass, treble and loudness controls; the speaker's previous
   settings are restored when KSLive stops.
- **Play audio** button for the live show (or latest available recording).
- `kslive.play` service for dashboards and automations, including an optional content ID and speaker override.
- Diagnostics redact authentication tokens and never expose signed playback URLs.

## Install with HACS

Until this repository is listed in the HACS default store:

1. In HACS, open **Integrations**.
2. Open the menu and choose **Custom repositories**.
3. Add this repository as category **Integration**.
4. Search for **KSLive**, download it, and restart Home Assistant.
5. Go to **Settings → Devices & services → Add integration → KSLive**.
6. Sign in and select the target speaker(s). You can change them later with **Configure**.

That setup creates the KSLive status sensor, Play and Refresh buttons, media player, output selector,
and all EQ preset controls automatically. Home Assistant dashboards are intentionally not modified by
integrations. The optional artwork card below requires the **Mushroom** and **Stack In Card** frontend
cards from HACS; the standard KSLive entities work without either frontend card.

For a manual installation, copy `custom_components/kslive` into Home Assistant's `config/custom_components` directory and restart Home Assistant.

## Using it

Press **KSLive Play audio**, or call:

```yaml
action: kslive.play
data:
  media_players:
    - media_player.living_room
```

To play a specific recording, also provide its `content_id`. IDs for the current show, next show, and latest recording are exposed as attributes on the **KSLive Audio status** sensor.

The Play audio button and `kslive.play` without `media_players` use your saved **KSLive Output**
selection. Supplying `media_players`, as in the example above, explicitly overrides that selection
for that playback session. Play resumes the current item while a session is active. From idle,
Play fetches the current catalogue and selects the live show or newest available recording.

Cast targets play the original HTTPS HLS stream. Sonos targets receive a private, short-lived MP3
relay generated by Home Assistant's FFmpeg integration, because Sonos cannot play HLS that also
contains video. Home Assistant and the speaker must be able to reach each other over the local network.
The player displays **Buffering** while Sonos opens the live relay; this normally takes a few seconds.

The **KSLive Player** entity also exposes Home Assistant's media browser and normal media-player
controls. Select the output with **KSLive Output** before pressing Play. If more than one speaker is
configured, choose **All configured speakers** to send the same stream to each of them. Separate
speakers may not be sample-synchronised; configure a native speaker-group entity when exact room-to-room
sync is required. The selected output is restored after Home Assistant restarts.
Output names come from Home Assistant's saved entity/device names and stay stable while the
integration is loaded, including while Sonos starts up. Reload KSLive after renaming a speaker
if you want its output label to update.

## Recommended dashboard card

For an artwork-backed player with playback, volume and speaker selection in one visual group, install
the **Mushroom** and **Stack In Card** frontend cards through HACS and add:

```yaml
type: custom:stack-in-card
mode: vertical
cards:
  - type: media-control
    entity: media_player.kslive_player
    name: KSLive
  - type: custom:mushroom-select-card
    entity: select.kslive_output
    name: Play on
    icon: mdi:speaker-multiple
    layout: horizontal
    fill_container: true
    tap_action:
      action: more-info
  - type: custom:mushroom-number-card
    entity: number.kslive_bass_preset
    name: KSLive bass
    icon: mdi:music-clef-bass
    display_mode: slider
  - type: custom:mushroom-number-card
    entity: number.kslive_treble_preset
    name: KSLive treble
    icon: mdi:music-clef-treble
    display_mode: slider
  - type: horizontal-stack
    cards:
      - type: custom:mushroom-entity-card
        entity: switch.kslive_eq_preset
        name: KSLive EQ
        icon: mdi:tune-vertical
        tap_action:
          action: toggle
      - type: custom:mushroom-entity-card
        entity: switch.kslive_loudness_preset
        name: Loudness
        icon: mdi:volume-high
        tap_action:
          action: toggle
```

The media-control card uses the current KSLive programme artwork as its background and includes the
player’s volume and transport controls. Changing **Play on** only changes the destination; it does
not start playback. The default KSLive EQ is a warmer bass +4, treble −2, with Sonos loudness on.
Changing the sliders saves the KSLive preset and updates an active KSLive Sonos session. The
integration captures the speaker’s previous EQ before playback and restores it on Stop, when
playback moves to another output, integration unload, or an externally detected stop/source change.
Simply selecting a different output leaves current playback running until Play is pressed.
If another app takes over one speaker, that speaker's EQ is restored without interrupting other
KSLive speakers. Controls whose original values are unavailable are left unchanged. Non-Sonos
outputs ignore the EQ preset. Restoration relies on Home Assistant receiving speaker state updates;
an abrupt power loss cannot run the normal shutdown restoration.

## Troubleshooting

- **Sonos stays on Buffering:** confirm the speaker can reach Home Assistant on the LAN and that
  Home Assistant's internal URL is valid under **Settings → System → Network**.
- **First Play is slower than Cast:** Sonos must open a fresh subscriber HLS stream through the local
   audio-only relay. KSLive allows a 30-second speaker startup window after EQ preparation.
  Repeated requests for the same item/output share the pending request, including while subscriber
  access is being resolved, and do not replace a buffering relay. This applies to the player, Play
  audio button and `kslive.play`. A different item or output is an intentional new request.
  A stream that never becomes active is cleaned up after its startup window; established streams
  also have a bounded 30-second allowance for rebuffering. KSLive uses the speaker's current media
  URL to distinguish its own stream from another app's playback.
- **No artwork card:** install Mushroom and Stack In Card, then add the YAML above. The integration
  cannot safely edit a user's dashboard during installation.

## Security and compatibility

### Idle sleep and account device limits

**Sleep when idle** is enabled by default for new and existing installations. While stopped, KSLive
does not poll the subscriber catalogue or refresh the login, including during Home Assistant startup.
The audio status shows `sleeping`; its attributes include the last successful catalogue timestamp
and indicate that displayed programme details are cached. Only display metadata is cached, never
subscriber tokens or playback URLs in that cache. After a fresh installation, use Refresh, Browse or
Play to populate the catalogue. Refresh and Browse do not start audio.

Play from idle fetches a fresh catalogue before selecting the live show or latest recording. Stop,
the end of playback or loss of the last owned speaker returns the integration to sleep. Paused
playback remains an active session so it can resume. To retain background catalogue updates, turn
off **Sleep when idle** under the integration's Configure options.

Sleep is **not sign-out**. Uscreen counts signed-in device sessions, so sleeping does not guarantee
that Home Assistant stops occupying a device slot. If the KSLive app reports too many devices, open
**Account → Devices** and sign out unused sessions. Removing Home Assistant's current session may
require reauthentication on the next explicit wake. The integration never removes your other devices
or signs back in automatically after you revoke its login.

Setup rejects an already configured account before sending a login request and keeps one device ID
across retries in the same setup flow. An existing integration also reuses its saved ID when
reauthenticating. Previously abandoned setups may still need removal in KSLive's Devices screen.
Automatic sign-out is not implemented: no verified subscriber API contract currently guarantees a
safe current-session release followed by password-free reconnection. Your password is not stored.

See [Uscreen's device session documentation](https://help.uscreen.tv/en/articles/7851857-device-sessions-limits).

This project is not affiliated with KSLive, King Kyle Group, or Uscreen. It is intended only for subscribers accessing content their account is authorized to play. It does not remove DRM, bypass subscription checks, or redistribute media.

KSLive uses Uscreen's subscriber app API and short-lived signed media links. Those private app endpoints can change without notice, so a future KSLive app update may require an integration update.
